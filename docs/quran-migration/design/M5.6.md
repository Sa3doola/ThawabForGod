# M5.6 — Quran settings, in-reader sheet, Sources, Mac spread threshold (lean)

## 1. Goal / out of scope
- One Quran settings form (Mushaf's `ReaderSettingsView` + `ContentPacksView`), shown both as **Settings → Quran** and as a **sheet from the reader toolbar**. Three new pack-choice keys. Sources change with the build (full vs public). Rule 3 of `MushafPageUnit` gets a ~18 pt floor.
- Out of scope: the backup and numerals rows (dropped, MAPPING :138); the order of search's attached translations (Later); bookmarks (M6); the Mac Quran menu (M7); new licence files (M8).

## 3. Data flow
- Every choice goes Form → `QuranSettingsViewModel` → `QuranReaderSettings.setX` → `SettingsStore`, and a key is written only by a control's setter. Pickers and toggles use `Binding(get:set:)`, so opening the screen writes nothing. Choosing "Automatic" for the default tafsir **deletes** the key (`setDefaultTafsir(nil)`).
- Capabilities: `QuranSettingsViewModel.load()` calls `await reader.load()`. That keeps `settings.apply` in one place, and the Mushaf mode row exists in Settings even before the Quran tab has been opened.
- Packs come from `translations.installed()` and `tafsir.installed()` in the view model. The panel, separated mode and the form filter them through the settings' enabled lists. `nil` means every installed pack, in store order. `[]` means all off, which is a real choice.
- The form's display-mode picker calls `reader.setDisplayMode(_:)`, which keeps the reader's place. It never calls `settings.select(displayMode:)` directly.
- Sources: `AboutViewModel.loadQuranSources()` reads `quran.capabilities()` and `packs.installed()` (`ContentPackStoring`). The only view that reads anything itself is `LicenceTextView`, through its existing bundle read.

## 4. Navigation
- `QuranCoordinator` gains `var isSettingsSheetPresented = false` and `func showSettings()`. `showSettings()` calls `closePanel()` first, because iPhone cannot show two sheets at once. This is state on the coordinator, not a path case.
- The sheet has its own `NavigationStack` and a local `@State var page: [QuranSettingsPage]` (`.packs`, `.sources`). These pushes are local to the sheet, not on the tab's path. Done dismisses the sheet.
- `SettingsRoute` gains two cases. `.quran` is a root row after `.reminders` (symbol `book`, title `.settingsQuranSection`). `.quranPacks` is one level in, like `.sources`, and is left out of `root`.
- The form's rows call closures. In Settings they call `coordinator.show(.quranPacks)` and `.show(.sources)`; in the sheet they call `page.append(...)`.
- No `AppRoute` or `DeepLink` change. The sheet is session state and closes on relaunch. Settings' path already survives a size-class change.

## 5. Batches (disjoint files)
**B1: preferences model + consumers + spread** (9 small edits)
- `SettingsStore.swift`: the 3 keys.
- `QuranReaderSettings.swift`:
  - properties `private(set) var enabledTranslations: [ContentPackID]?`, `enabledTafsirs: [ContentPackID]?`, `defaultTafsir: ContentPackID?`

  - `reset()` clears all three, and they join `stringKeys`
- `ContentPackSelection.swift`: port `M:Features/Content/ContentPackSelection.swift`, plus `static func enabledPacks(installed: [ContentPack], enabled: [ContentPackID]?) -> [ContentPack]` (nil → installed; otherwise the ids in order, skipping unknown ids).
- `AyahPanelViewModel.swift`:
  - `init(translations:tafsir:settings: QuranReaderSettings)` and a new `func enabledTranslations() -> [ContentPack]`
  - `enabledTafsirs()` passes `settings.enabledTafsirs`, and `currentTafsir` passes `settings.defaultTafsir`
  - `sections` checks `enabledTranslations().isEmpty`, and the translation cache is keyed on (ayah, enabled ids)
  - `pickedTafsir` stays session-only
- `AyahPanel.swift`: `LoadKey` gains `translations: [ContentPackID]`.
- `SeparatedTranslationsModel.swift`: `func load(surah: Int, isShown: Bool, enabled: [ContentPackID]?) async`, with `enabled` in the settle check. `SeparatedReaderView.swift`: `TranslationKey` gains `enabled`. The re-scroll must still happen only once (see Risks).
- `MushafPageUnit.swift`:
  - `nonisolated struct MushafSpreadFit: Hashable, Sendable { let pageAspectRatio: CGFloat; let linesPerPage: Int; let slotHeightEm: CGFloat; static let minimumFontSize: CGFloat = 18; func estimatedFontSize(in size: CGSize) -> CGFloat }`
  - The estimate: `pageH = min(size.height, size.width / 2 / pageAspectRatio)`, then `pageH / linesPerPage / slotHeightEm`.
  - `resolve(..., spreadFit: MushafSpreadFit? = nil)`: rule 3 returns `.spread` only if `spreadFit == nil || estimate >= minimumFontSize`, otherwise `.single`.
  - Rules 1–2 (fold, phone landscape) are the reader's own choices and stay as they are.
- `MushafPagerView.swift`: pass `MushafSpreadFit(pageAspectRatio: corpus.style.pageAspectRatio, linesPerPage: corpus.style.linesPerPage, slotHeightEm: RendererMetrics.glyphPerPage.slotHeightEm)`. Use the larger em so the estimate leans towards one page. No `#if os`: it applies wherever rule 3 does, which in practice means a Mac window or a small iPad Stage Manager window.

## 7. Saad's manual checklist
1. iPhone, full: in the reader, ellipsis → Reader settings. The sheet opens at medium height with the page still visible. Choose Sepia: the page behind it changes immediately.
2. iPhone, full: Translations & Tafsir → turn off Saheeh. Its text disappears from the separated rows, and the panel's Translation section goes. Turn it on again: both come back.
3. iPhone, full: enable two tafsirs, set the default to Muyassar, then open the panel on 2:255: Muyassar shows. Pick a different one in the panel and relaunch: the panel opens on the default again.
4. iPhone, full: Edit, then drag the tafsirs into a new order. The panel's picker shows the new order.
5. Any device: on a fresh install, open Settings → Quran and leave without touching anything. No `quran*` keys should be written (check with the debugger, or `defaults read` on the Mac App Group plist).
6. Any device, public build (`-quranData public`): Settings → Quran has no mode picker and no Mushaf pages section. Sources lists Tanzil and Jalalayn, and no KFGQPC/QUL rows.
7. iPad, full: the settings button is a direct toolbar button (regular width), and the landscape and open-flat rows are not shown.
8. Mac, full: ⌘, opens Settings; the Quran tab works and its pushes come back. A wide window shows a spread. Shrink the height until the text would fall under ~18 pt: it switches to one page and stays on the same page. Widen it again: the spread returns.
9. Mac: Reset in the sheet. Every row goes back to its default, and the keys are deleted rather than rewritten.
- Reviewer acceptance:
  - no `set(` on a key outside a setter
  - `nil` means "all installed" everywhere
  - no SwiftUI import in `ContentPackSelection`
  - `#if os` only in `QuranSettingsPlatform.swift` and the existing glue
  - the public build never names the KFGQPC/QUL data rows
  - the Quran text is untouched

## 8. Risks
- **Only chosen keys:** sliders and pickers write only on a user change, and `reset()` deletes keys. If the stored default tafsir has been disabled, the picker shows Automatic but leaves the key alone.
- **T4 / fallback:** the Mushaf section, the mode picker and the QUL source rows are all gated on `supportsMushafPages`, never on the file name.
- **T16:** if the default tafsir is silent on an ayah, the panel stays `.silent`; it never falls through to another pack.
- **Separated re-scroll:** the new `enabled` member reruns the `.task`. The jump-once guard must hold, or toggling a pack jumps the list (B1 to verify).
- **Stale panel:** the translation cache must miss when the enabled ids change. Otherwise the panel, and Copy, can still show a translation that was just turned off.
- **Spread flapping:** resizing the window near the threshold flips the unit. Re-anchoring keeps the same page; add hysteresis only if Saad sees flicker.
- **Mac Settings window:** a 9th tab in the 720 pt `TabView` may crowd its toolbar (checklist item 8).
- **T11:** the sheet's state lives on the Quran coordinator, so it never shows up in Hadith.

## Decisions for Saad
1. Enabled-list semantics: someone who has edited the list will find a pack added in a later build switched **off** (Mushaf's behaviour). Recommend keeping it.
2. The spread floor applies under rule 3 on every platform (no `#if`), not only on Mac. Recommend yes.
3. The QUL-derived Sources rows say "licence unsettled" until the KFGQPC/QUL requests are answered. Recommend yes, because it is honest. The licence texts themselves are new data and belong to M8.
