# M6.2 — Reader UI for bookmarks, notes, highlights (lean)

## 1. Goal
- The panel gets a bookmark toggle, a note button and editor, a highlight menu and a preview of the note. Both renderers draw the reader's marks from `QuranUserDataStore`: highlights are ayah-level bands, the ribbon sits on the Mushaf page and separated rows show bookmark and note icons. VoiceOver reads all three. The reader's toolbar (the "page header") gets a page bookmark toggle in Mushaf mode.
- Out of scope: the Library Bookmarks list (M6.3), the reading position, Home, recent searches (M6.4), an ayah context menu (Mushaf's `AyahContextMenu` was never ported; no new surface), VoiceOver *actions* for marks (the panel is the default action and has the buttons), and Mac menu commands or ⌘ shortcuts (M7).

## 3. Data flow
- `AppContainer.quranUserData` → `AppSectionView` → `QuranReaderView(userData:)`. From there it reaches:
  - the content, which passes `userData.marks` to `QuranReadingSurface.marks` (that parameter already exists and goes to both renderers);
  - the toolbar;
  - `quranAyahPanel(userData:)`, then `AyahPanel`, then `NoteEditorView`.
- **Invalidation rule (M6.1 review):** there is no `Canvas` in the Quran feature (grep confirmed). The store's dictionaries are observed wherever a mark closure is called, so **closures are called only at the top level of a leaf's `body`**. They are never called inside a `ForEach`, a `GeometryReader` or a lazy-stack closure, where tracking is not guaranteed:
  - `MushafUnitView.body` builds one snapshot for its 1–2 pages first, then passes it down;
  - `SeparatedAyahRow.body` builds its own snapshot from `marks`.
  - `QuranReaderContent` only *builds* `userData.marks`, which reads nothing, so a mark change never re-runs the reader or the pager row. Only the ≤3 units that are built re-evaluate. No revision counter is needed.
- Writes go only through `toggleBookmark`, `setNote` and `setHighlight` on the store. The panel's and toolbar's filled or empty states read `isBookmarked`, `note(for:)` and `highlight(for:)` in their own bodies.
- Bookmark haptic: `.sensoryFeedback(.impact(weight: .light), trigger:)` fires on *add* only (Mushaf).

## 4. Navigation
- No `QuranRoute`, `AppRoute` or `DeepLink` change. `QuranCoordinator` gains:
  - `var noteEditorAyah: VerseReference?`
  - `func editNote(_ ayah: VerseReference)`
  - `closePanel()` and `panelUsesInspector.didSet` both set it to `nil`.
- The editor is a `.sheet(item:)` that the **panel content** presents: on iOS it is a sheet over the panel sheet, like the tafsir reader. On the Mac it is a sheet from the inspector, sized by `quranNoteEditorFrame()`. No `.inspector` on iOS (`AyahPanelPresentation` stays as it is). This is session state, so it is not restored after a relaunch. The marks themselves persist (M6.1).

## 7. Saad's manual checklist
1. iPhone, full data, Mushaf mode: tap an ayah, then Bookmark. The ribbon appears on the page and the button shows filled. Tap again: both clear.
2. Same panel: Highlight → Green. The band sits under that ayah only, including the part that continues onto the next page. Select it: the selection draws over the band. Remove highlight: it clears.
3. Note → type in Arabic → Save. The note preview shows in the panel. Reopen it, empty the text, Save: the note is gone. Delete asks for confirmation first.
4. Toolbar page bookmark: filled on a page whose first starting ayah is bookmarked. A page that starts mid-ayah bookmarks the first ayah that starts on it. Immersive (tap the margin): the bars go, the ribbon stays.
5. Separated mode: highlighted rows are banded; note and bookmark icons sit at the row's outer top corner; the page button is gone.
6. **Kill and relaunch** (swipe away, reopen): every mark from steps 1–5 is still there in both modes.
7. iPhone, `-quranData public`: separated only, steps 3 and 5–6 pass, and no page bookmark button.
8. iPad landscape and portrait: the panel is always a sheet, the editor is a sheet over it, and rotating with the editor open keeps the reader pushed.
9. Mac: the panel is an inspector and the editor is a window sheet of at least 460×360. Same steps as 1–3, then quit with ⌘Q and relaunch.
10. VoiceOver (iPhone): a marked ayah on a page and in a row offers "more content": Bookmarked, Green, and the note text.
- Reviewer acceptance:
  - mark closures are called only at the top level of a leaf `body`;
  - no `Canvas`, no `.inspector` on iOS, no `#if os` outside the glue files;
  - colours come only from `ReadingPalette.highlight(_:)`;
  - copy and share still use `ayah.text`, and the editor draws but never stores Quran text;
  - no literal strings: every string is an `L10N-TODO` key from §6;
  - no `project.pbxproj` change, no SwiftData in views, and the page toggle is hidden when `!showsMushafPages`.

## 8. Risks
| Trap | Avoided by |
|---|---|
| Renderer not redrawing | snapshot built at the top level of the leaf `body`, so the dictionaries are observed there and no lazy or geometry closure is relied on |
| Over-invalidation | dictionary-level observation re-runs only the ≤3 built units and visible rows, once per tap, and never the reader or pager row |
| T4 Tanzil fallback | page toggle requires `showsMushafPages`; marks key on `VerseReference`, valid in both builds |
| T9 colours | no literal swatch; menu labels are names with a check (see Decisions); bands come from `palette.highlight` |
| Quran text altered | panel and editor draw through `QuranAyahText` (drawing-only fallback); `setNote` stores only the user's text |
| Immersive mode | toolbar toggle unreachable while hidden (acceptable: the panel still works); ribbon unaffected; VoiceOver already exits immersive |
| Sheet on sheet / size change | editor flag cleared in `closePanel` and `panelUsesInspector.didSet`, as the tafsir reader is |
| Action row overflow (small phone, Arabic, accessibility sizes) | third `ViewThatFits` fallback that scrolls |
| VoiceOver noise | indicators are `accessibilityHidden`; marks are custom content, so each ayah stays one element |

## Decisions
- Saad (M5), recorded: Copy/Share = original Arabic + [ref] + shown translations; tafsir pick is session-only; a tap always selects; iPad portrait uses a sheet. Translations inline only, nothing after An-Nas. The السماوات fold is confirmed. Packs added later start off. The spread floor applies everywhere. "Licence unsettled" rows stay until M8.
- Architect: invalidate by reading in the leaf `body`, not with a revision counter; an `Equatable` snapshot below the leaf.
- Architect: the VoiceOver key gets its own "Bookmark" noun (علامة), because Mushaf reused its button string, "إضافة علامة".

## Decisions for Saad
- **"Page header" toggle:** Mushaf has none. Recommend a toolbar button in Mushaf mode that toggles the page's *first starting ayah* only, so it never deletes other ayah bookmarks on the page. The ribbon still means "some ayah here is bookmarked", so it can show while the button is empty.
- **Note indicator on a Mushaf page:** recommend none drawn on the printed page. The page layout is exact and the outer margin holds the juz/hizb labels. The note shows in the panel, in VoiceOver and in separated rows.
- **Highlight swatches:** recommend no new opaque colour sets in M6.2. iOS menus draw item icons in one colour, so menu items are names with a check. The panel's Highlight icon is `circle.fill` in `palette.highlight(current)` with an ornament stroke. Add opaque `Reader/Swatch*` sets in M6.3 only if the list needs them.

## Added after review
- Marking an ayah redraws the page in place (no swiping away and back) in Mushaf and separated modes.
- Removing a highlight while the ayah is still selected leaves the selection showing.
- Arabic at the largest accessibility size: the panel's action row falls back to the scrolling layout.
- The toolbar page-bookmark button updates when the same ayah is bookmarked from the panel; the ribbon can show while the button is empty (it tracks only the first ayah that starts on the page, by decision).
- Separated rows: note/bookmark icons in the forced-RTL list, with a short and a long first line; make sure they don't cover the last word.
- iPhone in landscape, and a small phone in Arabic: the navigation bar's trailing items do not squeeze the title.
