# M7.1 design: iPad ayah-panel inspector, attached at the Quran stack (lean)
`Q/` = `ThawabForGod/Features/Quran/`. Nothing here was built or run. Why 647f769 reverted it: the comment in `Q/AyahPanel/AyahPanelPresentation.swift:16-18` (an `.inspector` on the reader, which is a `navigationDestination` inside the split view's detail column, pops the reader as soon as it presents).
## 1. Goal and scope
- iPad regular width + landscape (detail column wider than tall) shows the ayah panel as an **inspector**, attached to the Quran section's `NavigationStack` (not to the pushed reader), driven by the existing `QuranCoordinator` flags. Compact width or portrait: the reader's **sheet**, as today (M5.3 rule).
- **Out:** Mac (keeps its reader-level inspector, byte-for-byte), the note editor and "Read more" (stay sheets over the panel), fold/tabletop (M7.3), keyboard toggle (M7.2), any `QuranRoute` / `AppRoute` / `DeepLink` change.
## 2. Types
| Type / change | File | Isolation | Why |
|---|---|---|---|
| `AyahPanelLayout.usesInspector(size:isCompact:)` | `Q/AyahPanel/AyahPanelPresentation.swift` | `nonisolated enum` (unchanged) | iOS back to `!isCompact && size.width > size.height`; macOS `true` |
| `AyahPanelPresentation` (reader modifier) | same | `@MainActor` view modifier | Keeps the **sheet** (both platforms) and the Mac-only inspector; **loses** the measurement |

| `QuranCoordinator.isPanelInspectorShown` (new computed get/set) | `Q/QuranCoordinator.swift` | `@MainActor` (class) | Gate: `isPanelInspectorPresented && isReaderOnTop`; set `false` → `closePanel()` |
| `QuranCoordinator.showSurahInfo` | same | | Calls `closePanel()` first, like `showSearch` / `showBookmarks` |
| `QuranLaunchOptions.panelAyah`, `.forcesPanelInspector` | `Q/Debug/QuranLaunchOptions.swift` | DEBUG, `nonisolated` | The one repro run (§7) |
No isolation boundary is crossed: everything is main-actor view state; no `Task`, no actor.
## 3. Data flow
| Value | Owner | Read where |
|---|---|---|
| `panelAyah`, `isPanelSheetPresented`, `isPanelInspectorPresented`, `panelUsesInspector` | `QuranCoordinator` (unchanged) | flags only inside the two modifiers' bodies (M5.1: the reader's body never re-runs on open) |
| detail-column size + size class | the host modifier, `onGeometryChange` placed **after** `.inspector`, so it measures stack + inspector = the whole column and never flips when the inspector opens | writes `coordinator.panelUsesInspector` (`onChange(initial: true)`) |
| palette | host computes `theme.reading(reader.settings.resolvedTheme(systemColorScheme:))` from `@Environment(\.theme)` / `\.colorScheme` | panel view |
| faces, panel VM, reader VM, user data | `AppContainer` lets, passed by `AppSectionView` | `AyahPanel(isInspector: true)` |
- Measurement moves from the reader to the stack on **both** platforms (on the Mac it is constant `true`, so nothing changes there). The reader modifier keeps no geometry code.
- Rotation / Slide Over: `panelUsesInspector.didSet` (unchanged) moves an open panel between the stack inspector and the reader sheet. `MainInterfaceView` rebuilding into the tab bar rebuilds the stack; the host is on the stack in **both** arrangements (`AppSectionView` is shared), so `initial: true` re-measures.
## 4. Navigation
- No path change. The inspector is shown only while `path.last == .reader` (`isPanelInspectorShown`). `showSurahInfo` now closes the panel, as the other pushes already do; `open`, `popToRoot` already call `closePanel()`.
- Back/restore: unchanged; panel state is coordinator state, so a size-class swap keeps it.

## 8. Risks
- **T11:** the rule is measured on the detail column (stack), not the window and not the reader shrunk by the inspector. **Flip-flop:** measured outside the inspector, as M5.3 "Added after review" asked.
- **Unverified:** a stack-level `.inspector` inside `NavigationSplitView`'s detail on iPadOS 26 renders full height and leaves the pushed toolbar intact; the repro's "after" shot is the check. Fallback if it also pops: keep the sheet on iOS (revert A only).
- **Stale inspector over Search / Bookmarks / surah info:** gated on `isReaderOnTop`; pushes call `closePanel()`.
- **Hot path (M5.1):** the host reads `reader.settings` theme only (navigation rate), never the page or the selection.
## Decisions for Saad
1. **Mac keeps the reader-level inspector** (task says unchanged). Recommended: as designed; unify on the stack later only if the Mac shows a reason.
2. **The repro uses two DEBUG launch options** (`-quranPanel`, `-quranPanelInspector`) that stay in the codebase. Recommended: keep them (M7.3's Duo check reuses them).

## Outcome (2026-10-18)
Repro on iPad Pro 13" simulator, `-quranSurah 18`: with batch A's stack-level `.inspector` attached (never presented) the launch lands on the Library, i.e. the reader pops; with it disabled the reader stays. So **any** `.inspector` inside the split view's detail column pops a pushed reader. Per §8 fallback, batch A was reverted: iOS keeps the sheet. Only batch B (DEBUG `-quranPanel`, `-quranPanelInspector`) and the comment in `AyahPanelLayout` landed. Decisions 1 and 2 stand; the iPad inspector is not deliverable with `.inspector`.
