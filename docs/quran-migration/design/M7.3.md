# M7.3 design: iPhone landscape and the Duo panel / tabletop on `FoldGeometry` (lean)
`Q/` = `ThawabForGod/Features/Quran/`; Mushaf = `~/Desktop/Untitled Project/Mushaf/`. Builds on M7.1 (stack-level inspector host) and M7.2 (`isPanelOpen`). Nothing here was built or run.
## 1. Goal and scope
- **Landscape (iPhone):** the page rules are already ported (M4: `MushafPageUnit.resolve` rule 2, `.widthFit` scrolling page, `.twoPages` spread, the iPhone-only Landscape picker); M7.3 adds the one missing piece of Mushaf's full-screen landscape: the **tab bar hides** on the reader at compact height.
- **Duo, vertical fold (book / flat):** the ayah panel is an inspector exactly **one half** (trailing half + gutter, no text on the hinge), the pager shows one page in the other half. **Tabletop (horizontal fold, active):** page on the top half, `TabletopBottomView` on the bottom (the panel when open, else place + page buttons + hint). Mushaf `ReaderRootView.swift:70-149, 270-293`, `TabletopBottomView.swift`, `AppRouter.swift:67-83`.
- **Out:** adhkar `ArrangementView` (untouched, T12), iPad and Mac behaviour, Mac wheel paging, new settings.

## 3. Data flow
- **Vertical fold** is measured once, on the Quran stack by the M7.1 host (whole detail column, outside the inspector, as Mushaf measured "the whole reader, not the pager"). Stored on `coordinator.panelFold` (main-actor state, written in `onChange(of: measured, initial: true)` with `measured: FoldGeometry.Division?` Equatable). Inspector: `AyahPanel(...).padding(.leading, fold.gutterWidth).inspectorColumnWidth(fold.trailingWidth + fold.gutterWidth)`; without a fold the M7.1 `min 320 / ideal 380 / max 480`. The host sets `.environment(\.mushafPanelCoversFold, coordinator.isPanelInspectorShown && coordinator.panelFold != nil)` on its content; `MushafPagerView` uses `ignoresFold || panelCoversFold`.
- **Horizontal fold** is measured by `QuranReadingSurface` (the reading area below the navigation bar, so heights are the page's own) only in the `.mushaf where corpus.hasPages` branch. Tabletop → `VStack(spacing: 0) { MushafPagerView(..., isTabletop: true).frame(height: top); Color.clear.frame(height: gutter); tabletopBottom.frame(height: bottom) }`. Reports `onTabletopChange(tabletop != nil)` with `onChange(initial: true)`; separated mode reports `false`.
- `QuranReaderView` builds `TabletopBottomView(coordinator:panel:reader:userData:)` and the closure `{ coordinator.panelUsesBottom = $0 }` and hands both through `QuranReaderContent` to the surface. Its own body still reads nothing new (the bottom view reads the flags and `mushaf.page` in its own body).
- **Priority in `showAyah`:** `panelUsesBottom` → bottom; else `panelUsesInspector` → inspector; else sheet. `panelUsesBottom.didSet` (Mushaf): to bottom closes sheet / inspector and opens bottom; back out opens the inspector or the sheet per `panelUsesInspector`. `closePanel()` also clears `isPanelBottomPresented`. `isPanelOpen` adds `isPanelBottomPresented`.
- Fold simulation: `AppSectionView` (DEBUG) sets `.environment(\.foldOverride, QuranLaunchOptions.current.foldOverride)` on the Quran stack, so both the host and the surface see `-quranFold` / `-quranFoldHorizontal` (today only the reader's hooks set it).
## 4. Navigation
No path, route or link change. Panel state stays on the coordinator, so folding mid-read moves an open panel (sheet ↔ inspector ↔ bottom) and keeps its ayah.

## 7. Saad's manual checklist (iPhone 17 + Pro Max sim; full data unless said)
1. **Landscape, Mushaf, Landscape = One page:** the page fills the width and scrolls down; swipe for the next page; the **tab bar is hidden**, the nav bar stays (tap the page for immersive). Rotate back: tab bar returns, same page.
2. **Landscape = Two pages:** a spread; rotate back to one page on the same page.
3. **Landscape, separated and public (`-quranData public`):** the list reads normally; the tab bar is hidden on the reader only (Library still has it).
4. **Duo book pose (sim):** `-quranSurah 2 -quranAyah 255 -quranFold 0.5,24 -quranPanel 2:255` → panel fills exactly the trailing half; one page in the leading half; no text under the 24 pt gutter. Close → spread across the fold returns.
5. **Duo flat:** `-quranFold 0.5,0` with Open flat = Spread / Single page in Settings; panel as in 4.
6. **Tabletop:** `-quranFoldHorizontal 0.5,24 -quranMode mushaf` → page on top, controls below (surah, Juz · Page in the chosen digits, ← next / → previous, hint). Tap an ayah → panel below; Close → controls. Arabic UI mirrors the text but ← stays next.
7. **Tabletop, separated / public:** no split; the panel is the normal sheet.
8. iPad and Mac: no visible change (iPad landscape inspector from M7.1 still the default width).
**Reviewer acceptance:** one fold measurer for the panel (stack) and one for tabletop (surface), both through `FoldGeometry`; adhkar untouched; `#if os` only in glue files; `QuranReaderView.body` reads no panel flag; iOS + macOS build clean.
## 8. Risks
- **T12:** `FoldGeometry` stays the only fold code; nothing new under `Core/Layout`; `ArrangementView` untouched.
- **T11:** sizes from the stack / reading area, never the window. **Compact inner display:** if a Duo inner display reports compact width, `.inspector` presents as a sheet on its own; then the panel is a sheet, not half (acceptable fallback, check on device).
- **Hinge text:** gutter padding on the panel, `ignoresFold` on the pager while the panel covers a half.
- **Unverified:** whether the tab bar hidden on a pushed screen moves the page's safe area in landscape (the M5.1 chrome caveat); fallback: drop C.
