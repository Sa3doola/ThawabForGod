# M5.4 design: separated mode content (lean)
`Q/` = `ThawabForGod/Features/Quran/`; Mushaf = `~/Desktop/Untitled Project/Mushaf/`. Nothing here was built or run.
## 1. Goal and scope
One surah at a time (already true), each ayah followed by every installed translation when `showsTranslationInSeparated` is on, a "Next surah" footer, the header's Surah Info menu, and the place kept across rebuilds. Amiri renders end to end (basmala included).
A tap on an ayah already reaches `coordinator.showAyah` (M5.3's panel); M5.4 keeps that and only adds the translations under it, outside its tap target.
**Out:** inline tafsir (Decision 1); any new `SettingsKey`; an enabled/ordered translation list and the toggle's UI (M5.6); a font picker UI (M5.6; `-quranFont amiriQuran` until then, Decision 2); position across launches (M6 `ReadingPosition`); Previous surah, keyboard ⌘[ ⌘] (M7); bookmark/note marks (M6); `AppRoute`/`DeepLink` changes; the DEBUG scroll-through probe.

Boundary crossings: `[VerseReference: TranslationText]` from the `TranslationRepository` actor into the parse step, `[VerseReference: [AyahPanelTranslation]]` back; all three types are already `Sendable`. No `@Model`, no GRDB type leaves Data.
## 3. Data flow
- Packs: `TranslationRepositoring.installed()` (cached once in the model), all installed in that order (no enabled list until M5.6, same as `AyahPanelViewModel.enabledTafsirs`). Text: one `texts(surah:pack:)` per pack, never a query per row. A pack that throws is skipped (Mushaf's `try?`).
- Toggle: `QuranReaderSettings.showsTranslationInSeparated` (existing key `.quranShowsTranslationInSeparated`, default on). Read only; **no key added**.
- Public (Tanzil) build: `installed()` is empty, so rows draw Arabic only and no gap; Surah Info menu absent (no surah-info pack, `SurahInfoViewModel.isAvailable == false`). Next surah works in both builds.
- Position: `QuranReaderViewModel.separatedLocation` (unobserved, exists) stays the one source; the list reports `topAyah` and reads `initialAyah` once. Next surah goes through `coordinator.open(.surah(n))` (closes panel, sets location n:1, path unchanged).
- Rule kept from M5.1 3.4: `QuranReaderView` / `QuranReaderContent` never read the translations model; only `SeparatedReaderView.body` does (changes once per surah load).
## 4. Navigation
No new `QuranRoute`, `AppRoute` or `DeepLink`. Surah Info from the header = existing `coordinator.showSurahInfo(_:)` (pushes `.surahInfo(n)` above the reader); Back returns to the reader, which is rebuilt at `separatedLocation`. Panel prev/next across a surah boundary already works via `stepPanel` → `reader.open`.
**Restore cases that must hold:** pop to Library and Continue; switch tab and back; iPad crossing compact/regular; Mushaf ↔ separated toggle; back from Surah Info; text size change (anchor kept by `scrollPosition(id:anchor: .top)`).
**The one new fix:** the initial jump waits until the translations for this surah have settled, so rows above it do not grow after the jump and push the reader down.
## 5. Batches (disjoint files; all three can run in parallel)
**B1, the model (1 file):** `Q/Separated/SeparatedTranslationsModel.swift` (new). Port `loadTranslations()` + the `TranslationKey` idea from Mushaf `Features/Reader/Separated/SeparatedReaderView.swift` (lines 21-30, 150-167).
```swift
@Observable @MainActor
final class SeparatedTranslationsModel {
    init(repository: any TranslationRepositoring)
    /// The surah whose load (on or off) has finished; nil before the first.
    private(set) var settledSurah: Int?
    /// In pack order; [] when off, none installed, still loading, or `ayah` is not in the loaded surah.
    func translations(for ayah: VerseReference) -> [AyahPanelTranslation]
    /// Latest call wins; checks `Task.isCancelled` and the asked surah before applying. Off: clears and settles.
    func load(surah: Int, isShown: Bool) async
}
```
**B2, wiring (4 files):** `App/AppContainer.swift` (add `let quranSeparatedTranslations: SeparatedTranslationsModel`, built with the existing `quranTranslations`), `App/AppSectionView.swift` (pass it and `container.quranSurahInfoViewModel` to the reader), `Q/Reader/QuranReaderView.swift`, `Q/Reader/QuranReadingSurface.swift`. New params, exact:
- `QuranReaderView`: `let translations: SeparatedTranslationsModel`, `let surahInfo: SurahInfoViewModel` (after `panel`). Hands `QuranReaderContent` → surface `onNextSurah: { coordinator.open(.surah($0)) }` and `onShowSurahInfo: surahInfo.isAvailable ? { coordinator.showSurahInfo($0) } : nil`.
- `QuranReadingSurface`: `let translations: SeparatedTranslationsModel`, `var onNextSurah: (Int) -> Void = { _ in }`, `var onShowSurahInfo: ((Int) -> Void)? = nil`; passes `nextSurah: corpus.surah(separatedSurah + 1)` and the rest to the list. Keeps `.id(separatedSurah)`.
**B3, the list (3 files):** `Q/Separated/SeparatedReaderView.swift` (edit), `Q/Separated/SeparatedAyahRow.swift` (new, row moved out), `Q/Separated/SeparatedSurahFooter.swift` (new). B3 details: `.task(id: Key(surah, settings.showsTranslationInSeparated))` → `await translations.load(...)`, then the one-time initial jump (`@State didJump`) inside the same `ScrollViewReader`; replaces today's bare `.task`. ## 8. Risks
| Trap | How the design avoids it |
|---|---|
| M4/M5.1 3.4 re-evaluation cost | Model read only in the list body; rows get plain arrays; no observed per-scroll state |
| T13 isolation | `@MainActor` model, `@concurrent` parse, repository is an actor; only `Sendable` values cross |
| Neighbour text (T16 spirit) | `translations(for:)` returns [] unless the loaded surah matches; latest load wins |
| Restore drift | Jump after translations settle; `separatedLocation` stays the single source |
| T4 fallback | Empty pack list and `isAvailable` hide everything needing full data; nothing gated on build flags |
| Quran text unaltered | Basmala/rows go through `QuranAyahText` (drawing-only fallback); a11y uses `ayah.text` |
| T10 strings | One new key (+ optional hint), ar from Mushaf |
| T11 | Banner max width 560 and footer measured in the detail column; no window size read |
| LazyVStack laziness | Header, basmala, rows, footer stay direct siblings |
## Decisions for Saad
1. **Inline tafsir.** Mushaf has none; a group note spans several ayahs (T16) and needs a new key. **Rec:** translations only inline; tafsir stays in the panel. Public build then shows Arabic only inline, Jalalayn one tap away.
2. **Amiri picker before M5.6.** **Rec:** no interim UI; M5.6's in-reader sheet adds it, `-quranFont amiriQuran` for testing now.
3. **Footer at An-Nas.** **Rec:** nothing (Mushaf has no wrap-around); alternative "Back to Al-Fatiha".
