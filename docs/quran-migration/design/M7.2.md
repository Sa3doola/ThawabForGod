# M7.2 design: Quran keyboard commands and the Mac / iPad Quran menu (lean)
`Q/` = `ThawabForGod/Features/Quran/`; Mushaf = `~/Desktop/Untitled Project/Mushaf/`. Nothing here was built or run.
## 1. Goal and scope
- A **Quran** menu (Mac menu bar, iPad ⌘ overlay) whose items act only while the Quran section is the selected section (T11), plus unmodified paging keys in the reader on iPad hardware keyboards and the Mac. Mushaf's command table, keys and labels, ported.
- **Out:** Mac wheel/trackpad paging (`macWheelPaging`), multi-window, focusing the search field itself (`searchFocused` is iOS 18), Duo/tabletop (M7.3), any route change.

No boundary crossings: all main actor, no `Task`, no actor.
## 3. Data flow
- **Target**, built in `AppSectionView.quran`: `QuranCommandTarget(coordinator: container.quranCoordinator, reader: viewModel, userData: container.quranUserData, isSectionActive: { [router = container.router] in router.selectedTab == .quran })`, published with `.focusedSceneValue(\.quranCommandTarget, target)` on the stack. The live `isSectionActive` check covers a `TabView` that keeps other tabs' views mounted.
- **`isEnabled(_:)`** (cheap reads only; never `reader.location`, which tracks the page, so the menu is not re-validated per page turn, M5.1):
  - all: `isSectionActive()` and no blocking sheet (`!isSettingsSheetPresented && noteEditorAyah == nil && !isTafsirReaderPresented`; the panel itself does not block).
  - `.search`, `.goTo`: true. Everything else also needs `coordinator.isReaderOnTop && reader.corpus != nil`.
  - `.toggleDisplayMode`: `reader.canSwitchDisplayMode` (Tanzil: disabled). `.biggerText` / `.smallerText`: `!reader.showsMushafPages && settings.canEnlargeText / canShrinkText`.
- **`perform(_:)`** (guards `isEnabled`, then reads `location` freely):
  - next/previous page: Mushaf mode → `mushaf.canTurn(t)` then `mushaf.turn(t)` (spread-aware); separated → `corpus.ayah(after:/before: mushaf.selectedAyah ?? reader.location)` → `reader.open(.ayah(_))`.
  - `.goTo` → `coordinator.focusGoTo()` (pops to the Library, `goToFocusRequest += 1`; `QuranLibraryHeader` sets `isFocused = true` on change). `.search` → `coordinator.showSearch()`.
  - `.bookmark` → `userData.toggleBookmark(mushaf.selectedAyah ?? reader.location)`.
  - `.toggleAyahPanel` → `coordinator.toggleAyahPanel(at: mushaf.selectedAyah ?? reader.location)` (open → `showAyah`, open already → `closePanel`).
  - `.toggleDisplayMode` → `reader.toggleDisplayMode()`. `.nextTheme` → `settings.select(theme:)` with the next of `ReaderTheme.allCases`, wrapping.
  - previous/next surah → `s = (selected ?? location).surah`; if `1...114` contains `s ∓ 1`, `coordinator.open(.surah(_))`.
  - bigger/smaller → `settings.enlargeText()` / `shrinkText()`.
- No `SettingsKey` is new; theme and text size write their existing keys only when used.
## 4. Keys
| Command | Menu shortcut | Alternates | Notes |
|---|---|---|---|
| next / previous page | `←` / `→` (no modifiers, `localization: .withoutMirroring`) | Space, Page Down / ⇧Space, Page Up | RTL book: ← is next in **both** languages |
| previous / next surah | ⌘[ / ⌘] | | Mac: monitor, mirrored in an RTL UI as Mushaf (`NSApp.userInterfaceLayoutDirection`) |
| go to · search | ⌘G · ⌘F | | |
| bookmark · panel | ⌘D · ⌥⌘I | | |
| display mode · next theme | ⌘T · ⇧⌘T | | theme cycle is new (not in Mushaf) |
| bigger / smaller text | ⌘+ / ⌘- | ⌘= | |
- Menu groups (dividers): pages+surahs / goTo, search / bookmark, panel / mode, theme, bigger, smaller.
- **iPad:** the responder binds every shortcut and alternate as title-less `UIKeyCommand`s with `wantsPriorityOverSystemBehavior = true`, arrows `allowsAutomaticMirroring = false`; it claims first responder when `isActive` turns true. The menu lists each command once in the ⌘ overlay.
- **Mac:** menu shortcuts for all but Space/⇧Space/Page Up/Down and ⌘[ ⌘] (a `NavigationStack` takes those for Back/Forward), which the monitor maps; the monitor ignores events when `window.attachedSheet != nil` or the first responder is `NSText`. ⌘= is a hidden zero-size button in the reader's background.
- `isActive` for the key glue: `!isSettingsSheetPresented && !isPanelSheetPresented && noteEditorAyah == nil`; read in the glue modifier's own body, never in `QuranReaderView.body`.
## 5. Batches (disjoint; parallel)
| Batch | Files | Builds |
|---|---|---|
| **A** Table + menu | `Q/Commands/QuranCommand.swift` (new), `Q/Commands/QuranCommands.swift` (new), `App/ThawabForGodApp.swift` | §2, §3, §4 menu |
| **B** Key glue | `Q/Commands/QuranKeyInput.swift` (new) | iPad responder, Mac monitor, Mac alternates |
| **C** Wiring | `Q/QuranCoordinator.swift`, `Q/Library/QuranLibraryHeader.swift`, `App/AppSectionView.swift` | coordinator calls, ⌘G focus, publish target, attach keys |

**A** ports `Core/Platform/KeyCommands.swift` (enum, `ReaderCommands`) and `Features/Reader/ReaderCommandTarget.swift`. `ThawabForGodApp`: add `.commands { QuranCommands(localization: container.localizationManager) }` **outside** the `#if os(macOS)` (iPad gets it too); `SectionCommands` unchanged. Labels: `Text(localization.string(command.titleKey))`, implementers write `// L10N-TODO` keys.
```swift
nonisolated enum QuranCommand: String, CaseIterable, Identifiable, Sendable {
  case nextPage, previousPage, nextSurah, previousSurah, goTo, search, bookmark, toggleAyahPanel,
       toggleDisplayMode, nextTheme, biggerText, smallerText
  static let groups: [[QuranCommand]]; var titleKey: L10nKey; var systemImage: String
  var shortcut: KeyboardShortcut; var alternates: [KeyboardShortcut] }
@MainActor struct QuranCommandTarget {
  let coordinator: QuranCoordinator; let reader: QuranReaderViewModel; let userData: QuranUserDataStore
  let isSectionActive: () -> Bool
  func isEnabled(_ command: QuranCommand) -> Bool; func perform(_ command: QuranCommand) }
extension FocusedValues { var quranCommandTarget: QuranCommandTarget? { get set } }
struct QuranCommands: Commands { let localization: LocalizationManager }
```
**B** ports `Core/Platform/PagingKeyResponder.swift` and `MacInputMonitor.swift` (keys only; drop `WheelAccumulator`) and `ReaderKeyAlternates`. Assumes A:
```swift
extension View { func quranReaderKeys(target: QuranCommandTarget, isActive: Bool) -> some View }
```
**C** assumes A and B. Coordinator:
```swift
private(set) var goToFocusRequest = 0
func focusGoTo()                         // popToRoot(), then goToFocusRequest += 1
var isPanelOpen: Bool { get }            // isPanelSheetPresented || isPanelInspectorPresented (M7.3 adds the bottom panel)
func toggleAyahPanel(at ayah: VerseReference)
```
`AppSectionView`: build the target once in `quran`, `.focusedSceneValue(\.quranCommandTarget, target)` on the stack; on the `.reader` destination append a small private `ViewModifier` (in `AppSectionView.swift`) that reads the three flags and calls `.quranReaderKeys(target:isActive:)`. `QuranLibraryHeader`: `.onChange(of: coordinator.goToFocusRequest) { isFocused = true }`. `QuranReaderView.swift` is untouched.

## 7. Saad's manual checklist
1. **Mac, full:** Quran tab, reader on a Mushaf page: ← next page, → previous, Space / ⇧Space, Page Up/Down; spreads turn two pages. ⌘] next surah, ⌘[ previous. Arabic UI: ← still next page; the menu shows the brackets mirrored and the keys follow the menu.
2. **Mac:** ⌘D bookmarks the selected ayah (or the page's first); ⌘D again removes it. ⌥⌘I opens / closes the inspector. ⌘T switches mode; ⇧⌘T cycles Paper → Sepia → Dark. ⌘+ / ⌘= / ⌘- only in separated mode.
3. **Mac:** ⌘G from the reader → Library with the go-to field focused; ⌘F → Search. Switch to Hadith (⌘3): every Quran item is disabled, and ⌘F / ⌘D do nothing to the Quran. ⌘1-4 unchanged. Edit > Find is gone (decision 1).
4. **Mac:** with the note editor open, Space types into it and never turns a page; Settings sheet open → menu disabled.
5. **iPad (sim: I/O > Keyboard > Connect Hardware Keyboard), full:** hold ⌘ → the overlay lists the Quran menu. Arrows / Space page; ⌘[ ⌘] surahs; ⌥⌘I toggles inspector (landscape) / sheet (portrait).
6. **iPad:** on the Library, arrows do not page anything; type in the go-to field after ⌘G.
7. **Public (`-quranData public`), Mac + iPad:** ⌘T disabled; ← / → step one ayah in separated mode; ⌘+ / ⌘- work.
**Reviewer acceptance:** commands active only via `focusedSceneValue` + `isSectionActive`; nothing global; `isEnabled` never reads `location` or `mushaf.page`; `#if os` only in `QuranKeyInput.swift` and `ThawabForGodApp.swift`; no literal strings; iOS + macOS build clean.
## 8. Risks
- **T11:** scoped by focused scene value plus the live tab check; `SectionCommands` untouched; Hadith never sees a Quran shortcut fire.
- **Menu staleness:** if a `Commands` body does not re-validate on an `@Observable` change, `perform` still guards `isEnabled`, so a stale enabled item does nothing wrong.
- **Mac sidebar focus:** unmodified ← → as menu key equivalents win over the sidebar's own arrow navigation while the reader is on top. Accepted (Mushaf); the sidebar is a mouse target.
- **T10:** 11 new keys, one with new Arabic. **Hot path:** no new reads in `QuranReaderView.body`.
## Decisions for Saad
1. **Remove Edit > Find** (`CommandGroup(replacing: .textEditing) {}`) so ⌘F / ⌘G reach Search / Go to, as Mushaf did. App-wide on the Mac; Noor has no find-in-text. Recommended: yes.
2. **⌘T = Mushaf / Separated (Mushaf), ⇧⌘T = theme cycle (new).** Recommended: as designed.
3. **Theme cycle while "follow system" is on and the system is dark** shows Dark whatever is picked. Recommended: cycle the stored theme only (the change shows in light mode); alternative: cycling also turns follow-system off.
