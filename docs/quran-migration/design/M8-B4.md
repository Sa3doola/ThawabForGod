## 3. Data flow
- Publisher (app): one `DailyAyah` per list entry (`index` = list position), `listCount = list.entries.count`. Fresh = `listID == list.sha256 && first packID == translation id && entries.count == listCount`; no date in the check, so most foregrounds write nothing. An entry whose ayahs don't all resolve is **left out** (never shifted): the widget then shows the empty sentence that day, never another ayah.
- Widget: `dailyAyah(for:)` = `entries.first { $0.index == DailyAyahRule.entryIndex(for: date, count: listCount, calendar:) }`, device time zone (`DailyAyahRule.calendar`).
- Timeline: Ayah = entry at `now` + one at each of the next `daysAhead = 7` midnights, reload `.after(last)`; Continue = one entry, `.after(nextMidnight)`.
- Size: ~125 entries x Arabic + one translation, est. 150-250 KB in the App Group key. Test asserts < 512 KB.
- Fonts: `install(from: [hafsURL, amiriURL])` into `<group>/Fonts/`; widget registers each `.process`; `hasHafs` = Hafs PostScript name resolves. `QuranAyahText` then finds `AmiriQuran-Regular` registered with no change.
## 4. Navigation
None. `DeepLink`/`AppRoute` unchanged. Ayah tap `.quranVerse(first)`; Continue `quranPage ?? quranVerse`; empty `.quran`.
