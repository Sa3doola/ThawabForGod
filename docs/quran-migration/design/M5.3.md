# M5.3 design: the ayah panel (lean)
`Q/` = `ThawabForGod/Features/Quran/`; Mushaf = `~/Desktop/Untitled Project/Mushaf/`. Nothing here was built or run.
## 1. Goal and scope
Tapping an ayah selects it and opens Mushaf's panel: compact Hafs text, Copy / Share, then Translation | Tafsir with a tafsir picker. **Sheet** on iPhone and iPad portrait, **inspector** on iPad landscape and Mac (Mushaf's rule, measured on the reader view = the detail column, T11).
**Out:** context menu and bookmark / note / highlight (M6); fold / tabletop panel and keyboard toggle (M7); enabled-pack and default-tafsir keys (M5.6); inline translation (M5.4); a DEBUG panel launch option; any `AppRoute` / `DeepLink` change.

## 3. Data flow
| Value | Owner | Persisted |
|---|---|---|
| `panelAyah`, the sheet / inspector flags, `panelUsesInspector`, `isTafsirReaderPresented` | `QuranCoordinator` | no |
| The packs (loaded once), the ayah's translations, the tafsir phase, the requested section, the picked tafsir | `AyahPanelViewModel` (session, as Mushaf's router) | **no** (M5.6) |
| Corpus, `Ayah.text`, selection | `QuranReaderViewModel` | no |
| Palette, faces | `QuranReaderView` computes them; the modifier sets `\.readingPalette` and `\.quranFaces` | |
- **Sections:** `.translation` only if `translationPacks` is not empty. The public build has none, so it is **absent** (no "turn one on" text). `.tafsir` only if `currentTafsir != nil`. One section: no picker. At most one tafsir (public: Jalalayn): no menu.
- **Current tafsir:** `TafsirChoice.current(enabled: .enabled(installed:, enabled: nil), picked:, defaultTafsir: nil, appLanguage: language.rawValue)`.
- **Tafsir load (T16):** `nil` → `.silent(pack)` (`.tafsirSilent`); a throw → `.unavailable`. Same pack with the ayah in the loaded range: no reload. The old text stays until the new one is in. A result is applied only if its ayah and pack are still the ones asked for.
- **Copy / Share:** `Ayah.text` byte-for-byte (never `QuranAyahText` output, never the marker), then ` [Name s:a]` (digits from `l10n.string(_:grouped: false)`), then each loaded translation's `plainText` + `\n(pack name)`.
- **Drawing only:** `QuranAyahText.attributed(ayah.text, face: .kfgqpcHafs, …)` + NBSP + marker, as `SeparatedReaderView` does. Size is `@ScaledMetric`, seeded at 18 (sheet) / 22 (inspector). The 4-line cap's line height comes from `TextMeasurer`, kept in `@State` via `.onChange(initial: true)` and never computed in `body`.
## 4. Navigation
No new `QuranRoute`, `AppRoute` or `DeepLink` case. The panel is coordinator state outside the view tree, so it survives an iPad changing arrangement.
| Call | Does |
|---|---|
| `showAyah(_:)` (the tap) | `reader.select(ayah)` (now sets instead of toggling); sets `panelAyah`; opens the inspector or the sheet |
| `stepPanel(to:)` | Sets `panelAyah`, then `reader.open(.ayah(to))`, so the page or list follows |
| `panelUsesInspector.didSet` | Moves an open panel between sheet and inspector (`AppRouter.swift:54-65`) |
| `closePanel()` | Clears both flags and `isTafsirReaderPresented`; keeps `panelAyah` (no blank frame while the sheet animates out) |
- `open(_:)` and `popToRoot()` call `closePanel()` first, so a stale panel never returns. "Read more" is a sheet over the panel.
- The sheet's toolbar has prev / next and Done. The inspector has no toolbar (macOS merging is unverified): prev / next / **Close** sit in a row above the Arabic.

## 7. Saad's manual test checklist
- **iPhone 17, full:** tap 2:255 → medium sheet with the Arabic faded after 4 lines; "Show the whole ayah" raises it. Saheeh's footnotes open. The Tafsir menu offers 3; switching keeps the ayah. Prev / next move the page underneath. Copy, then paste in Notes → the Arabic identical to the page + ` [Al-Baqarah 2:255]` + the translation; Share gives the same. Arabic UI with Arabic-Indic digits → `البقرة ٢:٢٥٥`.
- **iPad, full:** landscape → inspector with Close. Rotate to portrait while open → sheet on the same ayah; rotate back → inspector. Switch tab and back → still open.
- **Mac, full:** click → inspector. "Read more" opens the full tafsir. Paste in TextEdit → original text. A narrow window keeps the inspector.
- **Public (`-quranData public`), iPhone + Mac:** no Translation section, picker or menu; Jalalayn directly. An ayah Jalalayn skips → "This commentary has no note on this verse.". Copying an ayah with the silent-letter mark keeps Tanzil's character.
- **Reviewer acceptance:** no view calls a repository; Share gets `Ayah.text` unmodified; `.translation` gated on installed packs; `nil` → `.silent`; no `SettingsKey` written; `#if os` only in the two glue files; no literal colour or size; iOS and macOS build clean.
## 8. Risks
- **T16:** silence and failure are two phases, and a neighbour is never fetched. **T9:** `FadeMask` and palette tokens. **T10:** 12 new keys, every number through `l10n`. **Text:** copy and share never touch `QuranAyahText`.
- **T11:** the rule is measured on the reader view. **Unverified:** `.inspector` on a pushed view inside `NavigationSplitView` on iPad (fallback: the sheet on iPad). **T13:** `@concurrent` parse, `Sendable` values, a "still asked" guard. **Hot path:** the flags are read only in the modifier, and `panelAyah` only in `AyahPanel`.
## Decisions for Saad
1. **Share / Copy content.** Recommended: Mushaf's (original Arabic + `[reference]` + the shown translations with their names). Alternative: Arabic + reference only. The public build has no translations, so the two are the same there.
2. **Panel tafsir pick is session-only** (Mushaf). Recommended: keep it; M5.6 adds a default in Settings.
3. **A tap always selects** (no toggle); the selection stays after closing (Mushaf). Recommended: as designed.
4. **iPad portrait uses a sheet**, because an inspector would leave about 400 pt for the page. Recommended: as designed.
