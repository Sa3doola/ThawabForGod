# M6.3 — Library Bookmarks list (lean)

## 1. Goal
- One screen pushed from the Library toolbar that lists the reader's bookmarks, notes or highlights (segmented). It sorts by date (newest first) or by surah (Mushaf order, one section per surah). Swipe or context menu deletes. A tap opens the ayah in the reader. Notes can be edited from the context menu.
- Out of scope: reading position, Continue reading, Home, recent searches (M6.4); Mac ⌘ shortcuts and "open in new window" (M7); search or filter inside the list; export; "clear all"; reaching the list from the reader toolbar.

## 2. Types (all in `Features/Quran/Bookmarks/`)
| Type | File | Isolation | Why |
|---|---|---|---|
| `QuranMarkKind` (bookmarks/notes/highlights), `QuranMarkOrder` (date/surah) | `QuranMarkList.swift` | `nonisolated enum: CaseIterable, Identifiable, Sendable` | pure values; port of Mushaf `BookmarkKind`/`BookmarkOrder` |
| `QuranMarkRow`, `QuranMarkSection`, `QuranMarkList` (pure sort) | same | `nonisolated struct/enum, Hashable, Sendable` | ordering is a pure function, with no view involved |
| `QuranBookmarksViewModel` | `QuranBookmarksViewModel.swift` | `@MainActor @Observable final class` | kind, order and the edited note live outside the view tree (they survive an iPad size-class swap) |
| `QuranBookmarksView` | `QuranBookmarksView.swift` | MainActor view | the screen |
| `QuranMarkRowView` | `QuranMarkRowView.swift` | MainActor view | one row |
- Nothing crosses an isolation boundary: the store and the reader view model are `@MainActor`, and deletes go through the store's synchronous setters.

## 3. Data flow
- `AppContainer.quranUserData` (M6.1) → VM. The VM reads only the selected kind's array (`bookmarks` / `notes` / `highlights`), so changing a mark re-runs only this screen.
- Row date: bookmark `createdAt`, note `updatedAt`, highlight `updatedAt`. By date: newest first; on a tie, Mushaf order. By surah: sections in ascending surah order, ayahs ascending.
- Corpus: `.task { await viewModel.prepare() }` → `reader.load()` (same as Search). **The list does not wait for the corpus.** It shows when `userData.isLoaded`. Every corpus-dependent part is optional: with no corpus (still loading, failed, or a stale ayah, see M6.1 risk), the row shows the numeric `s:a` reference only, with no name and no excerpt. Until `isLoaded`: `ProgressView`.
- Reference string: same as `QuranSearchView.reference` (one string, `l10n.string(_:grouped:false)` digits, `corpus.surah(n)?.name(in: l10n.language)`). Section header: `"n. Name"`, as in search's `groupHeader`.
- Excerpt: `QuranAyahText.attributed(ayah.text, face: .kfgqpcHafs, scaledSize:, hafsIsRegistered: faces.contains(.ayahText))` with `faces.font(.ayahText, size:)` (`@ScaledMetric` 17). It has 2 lines (1 when a note shows), is `\.layoutDirection(.rightToLeft)` on that leaf only, and uses `palette.secondaryText`. **Drawing only**: nothing is stored or copied.
- Note text: `Text(verbatim:)`, 3 lines. Highlight swatch: a 12pt `@ScaledMetric` `Circle` filled with `palette.highlight(color)` and stroked with `palette.ornament`, labelled `color.titleKey` (M6.2). No new colour sets.
- Date (by-date order only): `l10n.shortDateString(date)` (honours the digit setting), trailing, `palette.secondaryText`.
- Palette: `theme.reading(settings.resolvedTheme(systemColorScheme:))`, as Search uses; set on the list background and re-applied as `\.readingPalette` on the note-editor sheet. `\.quranFaces` already comes from the section.
- Deletes: bookmarks → `setBookmarked(false, ayah:)`; notes → `setNote("", for:)`; highlights → `setHighlight(nil, for:)`. No view touches SwiftData.
- Kind and order are **session-only** VM state (default bookmarks / date). No `SettingsKey`.

## 4. Navigation
- `QuranRoute.bookmarks` (new, no payload). `QuranCoordinator.showBookmarks()`: `closePanel()`, then append `.bookmarks` unless it is already `path.last`. `QuranCoordinator` has no other change; the reader stays `path[0]`.
- Opening a row: `coordinator.open(.ayah(row.ayah))`, which replaces the stack with `[.reader]` (as a Search result does). Back returns to the Library. For a stale ayah with the corpus loaded, `reader.open` returns false, so nothing moves. With the corpus not yet loaded, the existing parked-target take-back applies.
- No `AppRoute` or `DeepLink` change. Restore: the path is on the coordinator, so it survives a compact/regular swap. A relaunch starts at the Library (as Search does).

**Batch A, the screen:**
- `List` with one `Section` per `QuranMarkSection`. A header only when `surah > 0` and the corpus is loaded; otherwise it uses the numeric surah.
- Picker: `.segmented`, in `.safeAreaInset(.top)` on `palette.background`, with the hidden label `quranMarksShow`.
- Title: the kind's title, inline.
- Toolbar: `.primaryAction`, a `Menu` holding an inline `Picker` over `QuranMarkOrder` (icon `arrow.up.arrow.down`, label `quranMarksSort`).
- Row: a `Button` that opens the ayah, `.tint(palette.text)`, `.listRowBackground(palette.background)`, `.accessibilityElement(children: .combine)`.
- Delete: `.swipeActions(edge: .trailing, allowsFullSwipe: kind != .notes)`, a destructive `quranMarksDelete` button.
- `.contextMenu`, on Mac and iOS (no `#if`): for notes, `quranNoteEdit` (only when `corpus.ayah` exists), then Delete.
- A note's Delete from either the swipe or the menu goes through a `confirmationDialog` (`quranNoteDeleteConfirm`). Bookmarks and highlights delete immediately (Mushaf).
- Editor: `.sheet(item: $viewModel.editingNote)` → `NoteEditorView(ayah:reference:userData:)` + `.environment(\.readingPalette, palette)` + `.quranNoteEditorFrame()`.
- Empty state, as an overlay when sections are empty: `ContentUnavailableView`, title per kind, icons `bookmark` / `note.text` / `highlighter`, description `quranMarksEmptyHint`.
- Identifiers: `quran.bookmarks.list`, `quran.bookmarks.row`, `quran.bookmarks.empty`.

Exact interfaces:
```swift
// A provides (B uses):
@MainActor @Observable final class QuranBookmarksViewModel {
    var kind: QuranMarkKind = .bookmarks; var order: QuranMarkOrder = .date; var editingNote: VerseReference?
    init(userData: QuranUserDataStore, reader: QuranReaderViewModel)
    var isLoaded: Bool { get }; var corpus: QuranCorpus? { get }; var sections: [QuranMarkSection] { get }
    func prepare() async; func delete(_ row: QuranMarkRow) }
struct QuranBookmarksView: View { init(viewModel: QuranBookmarksViewModel, coordinator: QuranCoordinator, settings: QuranReaderSettings) }
nonisolated struct QuranMarkRow: Identifiable, Hashable, Sendable { let ayah: VerseReference; let date: Date
    var note: String?; var color: HighlightColor?; var id: VerseReference { ayah } }
nonisolated struct QuranMarkSection: Identifiable, Hashable, Sendable { let surah: Int /* 0 = by date */; let rows: [QuranMarkRow]; var id: Int { surah } }
nonisolated enum QuranMarkList { static func sections(_ rows: [QuranMarkRow], order: QuranMarkOrder) -> [QuranMarkSection] }
extension QuranMarkKind { var titleKey: L10nKey; var emptyKey: L10nKey; var systemImage: String }
// B provides (A uses): QuranRoute.bookmarks; QuranCoordinator.showBookmarks(); existing open(_:) / editNote unchanged.
```

## 7. Saad's manual checklist
1. iPhone, full data, `-quranSeedUserData YES`: Library → bookmark button → 5 bookmarks, newest first, with dates in your digit setting. Switch to Notes (3) and Highlights (6, with coloured dots).
2. Sort → By surah: a section per surah ("2. Al-Baqara"), with ayahs ascending and no dates. Switch kind: the order is kept.
3. Tap a row: the reader opens on that ayah (in Mushaf and in separated mode). Back lands on the Library, not on the list.
4. Swipe a bookmark: it is deleted at once. A note: no full swipe, and Delete asks to confirm. Then reopen that ayah's panel: the mark is gone.
5. Notes → long-press → Edit note: the editor opens. A save shows in the row at once.
6. Remove every highlight: the empty state shows with its hint (Arabic too).
7. **Kill and relaunch:** deleted marks stay deleted, and kind and sort are back to Bookmarks / By date.
8. iPhone, `-quranData public`: the same list, with names and excerpts drawn (with the Hafs fallback where needed).
9. iPad landscape ↔ portrait with the list open: it stays open with the same kind and sort. Mac: right-click → Delete / Edit note; a trackpad swipe deletes; the editor is ≥460×360.
- Reviewer acceptance:
  - no `#if os` and no SwiftData in the new files;
  - colours only from `ReadingPalette`;
  - the excerpt goes through `QuranAyahText`, and nothing stores Quran text;
  - every string is an `L10N-TODO` key from §6;
  - the list renders with `corpus == nil`;
  - the VM reads only the selected kind's array;
  - no `project.pbxproj` change.

## 8. Risks
| Trap | Avoided by |
|---|---|
| T4 Tanzil fallback | nothing page-based is shown; marks key on `VerseReference`; the list works in both builds |
| T7 identity | rows keyed on `VerseReference`; delete by ayah |
| T9 colours | swatch = `palette.highlight` with an ornament stroke; no literal or new colour set |
| T10 strings | the 13 keys in §6, both languages |
| T11 tab/split | pushed on the section stack; the path lives on the coordinator |
| Stale or unloaded corpus | optional excerpt/name; tapping a stale row moves nothing (`reader.open` returns false) |
| Accidental note loss | no full swipe on notes, plus confirmation |
| Quran text altered | drawing-only fallback via `QuranAyahText`; deletes write only the user's data |

## Decisions
- Saad (M5), recorded: see M6.2 §Decisions (Copy/Share, session tafsir, tap selects, iPad sheet, inline translations, السماوات fold, packs start off, spread floor, licence rows).
- Architect: one screen with a segmented control (Mushaf), not sections; kind and sort are session-only on the VM; the list does not wait for the corpus; new `quranMarks*` keys rather than reusing the legacy `quranBookmarksEmpty` (its wording describes the old UI).

## Decisions for Saad
- **Note deletion:** recommend no full swipe and a confirmation for notes only (they are the user's own writing); bookmarks and highlights delete at once, like Mushaf. No undo.
- **Sort persistence:** recommend session-only. Persisting would take a `SettingsKey.quranMarksOrder`, written only on a pick: trivial if you want it.
- **Legacy key** `quranBookmarksEmpty` is unused: delete it at M8 cleanup.
