# M9: book-style page turning (page curl)

## 1. Goal
iOS/iPadOS Mushaf pages turn with a `UIPageViewController(.pageCurl)` laid out as an Arabic book: spine on the right, the next page lifts from the left edge.
Reading Options gets "Page turn: Book / Slide". Slide is today's pager, unchanged; macOS always slides.
Out of scope: separated mode, immersive mode, ayah panel / sheet / tabletop bottom, reading position, selection, `MushafPagerStep` maths, `MushafPageUnit` rules, tests (lean mode).

## 3. Data flow
- The page is `MushafReadingState.page`, owned by `QuranReaderViewModel`. Key and menu paging (`QuranCommand.turn`, `state.turn`) and Go to (`state.show(page:)`) only change the state, and each pager mirrors it. Nothing new on the view model.
- The curl's `Coordinator` watches `state.page` with `withObservationTracking`, re-armed after each change, and calls `sync()`. It does not depend on SwiftUI calling `updateUIViewController`.
- A finished curl gesture reads the page from `pvc.viewControllers`, checks it with `MushafPagerStep.accepts(reported:page:pageCount:jumpTarget:nil)`, then calls `state.show(page:)` only if `state.page` is not already in the unit (the B3 guard reused).
- Choice: `settings.pageTurn` (`SettingsKey.quranPageTurn`) is written only by the picker. Effective mode, decided in `MushafPagerView`:
  `curl = MushafPagerPlatform.supportsCurl && settings.pageTurn == .curl && !reduceMotion && !voiceOverEnabled && unit != .widthFit`
- Font window (T1): the existing `.task(id: state.page) { prepare(around:) }` moves out of the slide branch so it serves both modes. The curl adds no font work of its own.
- No view touches GRDB, SwiftData or files. The hosted pages get the same `services` / `corpus` / `marks` as today.

## 4. Navigation
No change to `QuranCoordinator`, `QuranRoute`, `AppRoute` or `DeepLink`. Back and restore go through the reading position as today.
Switching Book and Slide while reading keeps the page: either pager opens at `unit.unitStart(for: state.page)`. On the Slide side, `.task(id: unit)` already jumps there on appear.

## 5. Batches (no shared files, all 3 can run in parallel)
**B1 Settings** (5 files): `Domain/QuranReaderPreferences.swift`, `Shared/Settings/Domain/SettingsStore.swift`, `Settings/QuranReaderSettings.swift`, `Settings/QuranSettingsPlatform.swift`, `Settings/QuranSettingsForm.swift`.
- Model the enum on `FlatOpenLayout`. Model the setting on `flatOpen`: read with a fallback, `select` writes its one key, `reset()` sets it back to `.fallback`, and the key goes in `stringKeys`.
- Form: a new `pageTurnSection` with a Picker over `allCases` and a footer, `accessibilityIdentifier("quran.settings.pageTurn")`. Shown only inside the existing `capabilities.supportsMushafPages` gate and when `QuranSettingsPlatform.showsPageTurn`, so the Tanzil build and the Mac never show it. Strings are `L10N-TODO`.

**B2 Curl engine** (3 new files): `Mushaf/MushafCurlPlatform.swift`, `Mushaf/MushafCurlOrder.swift`, `Mushaf/MushafCurlPage.swift`. No Mushaf source (Mushaf never had a curl).
- `MushafCurlPlatform.swift` is the only new `#if os`. It holds `supportsCurl`, the `MushafCurlPager` view, and the representable behind `#if os(iOS)`.
- Spine is init-only, so B3 puts `.id(unit)` on `MushafCurlPager`. `.single` uses `.max` with `isDoubleSided = false`. `.spread` uses `.mid` with `isDoubleSided = true` (required) and two controllers in the order `[first + 1 (left, even), first (right, odd)]`.
- Set `pvc.view.semanticContentAttribute = .forceLeftToRight` so UIKit never mirrors on its own. The direction is entirely `MushafCurlOrder`'s, and the same in en and ar.
- `MushafCurlOrder`, per spine:
  - `.max`: UIKit "after" is reading page + 1, and `.forward` means next.
  - `.mid`: UIKit order is the reverse of reading order, so "after" is page − 1 and `.reverse` means next.
  - If a device shows either one backwards, the fix is one line here (see Risks).
- Swipe only: in `make`, remove every `UITapGestureRecognizer` in `pvc.gestureRecognizers` from `pvc.view`. Leave the pan recognizer and its delegate alone.
- Turn guard:
  - `isTurning` is set in `willTransitionTo` and in `setViewControllers(animated: true)`, and cleared in `didFinishAnimating` or the completion.
  - While `isTurning` is set, `sync()` keeps only the latest `pendingTarget` and applies it afterwards, because `setViewControllers` during a gesture asserts.
- `sync()`: `target = unit.unitStart(for: state.page)`. If it equals the displayed unit, do nothing. Otherwise animate only when `abs(target - displayed) == unit.pageCount`, and set the page without animation for anything further (Go to, ⌘[ ⌘]).
- Pool, so no allocation per turn: `[Int: UIHostingController<MushafCurlPage>]`, at most 3 units (3 controllers single, 6 spread). A miss reuses the controller farthest from `state.page` that is neither visible nor pending, by setting `rootView`, and only creates a controller below the limit. Each controller is set with `safeAreaRegions = []` and `view.backgroundColor = UIColor(palette.background)`.
- Environment: hosting controllers do not inherit SwiftUI's environment. `update` stores `context.environment`, and each page applies `.environment(\.self, env)` then `.environment(\.layoutDirection, .rightToLeft)`. That carries `LocalizationManager`, `QuranReaderSettings`, the theme, `readingPalette`, `quranFaces`, `surahHeaderFrame`, `forcedRenderer`, `mushafChromeToggle` and Dynamic Type.
  - Live controllers are refreshed only when `MushafCurlRefresh: Equatable` changes: unit, fold, side insets, palette, `colorScheme`, `dynamicTypeSize`, `quranFaces`, `showsMarginMarkers`. This avoids three page redraws per turn.
- `MushafCurlPage(corpus:state:settings:services:page:gutter:marks:fontCap:onSelect:)`:
  - Mirrors `MushafUnitView.pageView`. Read `marks.snapshot` and `state.selectedAyah` at the top level of `body`, so selection redraws by observation.
  - `.contentShape(.rect).onTapGesture { chromeToggle?.toggle() }` as `MushafUnitView` does.
  - Spread: `.environment(\.mushafFontSizeCap, fontCap.cap(for: page))` and `.onPreferenceChange(MushafFontSizeKey.self) { fontCap.sizes[page] = $0 }`. The cap is the minimum over the page and its partner (odd n pairs with n + 1).
  - A fold pads the spine side by `gutterWidth / 2`.

**B3 Wiring** (1 file): `Mushaf/MushafPagerView.swift`.
- Keep the GeometryReader, fold, `unit(for:)` and side insets. Move the existing `ScrollViewReader` block, unchanged, into `slidePager(unit:fold:sideInsets:proxy...)`. Branch on the effective mode from section 3.
- Shared by both modes: `.onChange(of: unit.pageCount, initial: true)` and `.task(id: state.page) { prepare }`.
- Extract `MushafPagerUnits.chromeToggle` into `static func MushafChromeToggle.pager(state:voiceOverEnabled:reduceMotion:) -> MushafChromeToggle?` and apply it to both branches.
- Fold spread in curl: frame the curl at `2 * min(leadingWidth, trailingWidth) + gutterWidth`, aligned as the Slide spread aligns its pages, so the spine sits on the hinge.
- VoiceOver: on a `state.page` change while VoiceOver is on, post `AccessibilityNotification.Announcement(l10n.string(.quranPageNumber, l10n.string(page, grouped: false)))`.

## 7. Acceptance checks (reviewer)
- The only new `#if os` is in `MushafCurlPlatform.swift`, and the macOS build compiles with `MushafCurlPager` as `EmptyView`.
- `.quranPageTurn` is written only in `select(pageTurn:)`, and it is in `stringKeys` and `reset()`.
- No `UITapGestureRecognizer` is left on the curl's view. `setViewControllers` is never called while `isTurning`, and is animated only for a ±1 unit step.
- The pool never exceeds 3 units and never reuses a visible or pending controller.
- The Slide code path is byte-for-byte the old one, only moved into a function. `MushafPagerStep` and `MushafPageUnit` are untouched.
- Quran text is untouched: a curl page is the same `MushafPageView`.

## 8. Risks
- **RTL / spine direction (high).** UIKit's "forward" with `.max` versus `.mid` is not documented clearly. Mitigation: everything sits in `MushafCurlOrder` plus `.forceLeftToRight`, and the checklist tests both spines in both languages. A wrong direction is a one-line fix.
- **`.mid` spine.** It needs exactly 2 controllers or it crashes ("number of view controllers…"). The pairs are 1|2 through 603|604, and 604 is even, so no orphan page.
- **Spine not on the hinge.** The spine is the curl view's centre, so B3 centres the frame on the fold (T12). An off-centre fold shows as a gutter misplaced by a few points; Saad checks on the Duo.
- **Gesture conflicts.**
  - Taps: the tap recognizers are removed, and SwiftUI taps never start a pan.
  - widthFit's vertical scroll fights the curl's pan, so widthFit (iPhone landscape one page, tabletop) slides (decision D1).
  - The system back-swipe from the left screen edge in an English UI can win over a forward curl started at the edge (D3).
- **Hosting environment.** `\.self` copies the whole environment, but `@Observable` objects only redraw if read inside `body`, which they are. If a value goes missing (fonts or theme fall back to defaults), list it explicitly in `MushafCurlPage`.
- **Key responder.** The pages' hosting controllers must not take first responder from `QuranKeyResponder`. They have no key commands, but Saad checks ← → after a curl on iPad.
- **T11:** the unit is decided from the pager's own size, unchanged. **T1:** fonts stay on the ±3 window, unchanged. **T13:** all UIKit is `@MainActor`, measurement stays in `PageMetricsCache`. **T9 / T10:** no literal colours, all strings are keys.
- **VoiceOver.** Curl is off while VoiceOver runs (D2), so the three-finger scroll is today's. The announcement may double up with the scroll view's own "page" speech; Saad listens.

## Decisions for Saad
- **D1** iPhone landscape one-page (widthFit) and tabletop: **Slide** (recommended), because a vertical scroll inside a curl fights the pan. The two-pages landscape layout does curl.
- **D2** VoiceOver running: **Slide** (recommended), which keeps today's three-finger paging exactly. Building `accessibilityScroll` for the curl is the alternative.
- **D3** Back-swipe at the left edge: leave the system gesture alone (recommended) and re-check on device. If it steals forward turns, make the interactive pop require the curl's pan to fail.
- **D4** "3 controllers" read as 3 units: a spread needs 2 controllers per unit, so up to 6 hosted pages.
- **D5** The prompt's checklist says "spread pairs (2-3, 50-51)", but the prompt and `MushafPageUnit` say odd on the right, which gives 1|2, 3|4, 49|50, 51|52. Keep the existing rule (recommended). If the printed pairing really is 2|3, that is a `MushafPageUnit` change, outside M9.

### Added after review (Saad's extra checks)
- (a) iPhone landscape, two pages (curls): the outer margins match Slide on a notched phone.
- (b) Start a curl and let go half-way so it cancels, then press ← → and use Go to: both still work.
- (c) Mash ← quickly during a curl: it lands on the right page, never a wrong one.
- (d) Rotate or fold mid-curl: no crash, same page.
- (e) Bookmark, highlight or select on a curl page: it redraws at once.
- (f) Change reader theme, Dynamic Type and accent while on a curl page (accent and renderer are not in the refresh key, so it may lag until the next page turn).
- (g) iPad landscape, open and close the ayah side panel: the curl rebuilds on the same page.
- Known and unfixed: `isTurning` is cleared only in `didFinishAnimating` or the `setViewControllers` completion; if UIKit ever skips it, keys and Go to would stop working. Look for that while mashing.
