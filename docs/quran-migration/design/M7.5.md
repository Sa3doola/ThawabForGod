# M7.5 design: Continue Reading and Ayah of the Day widgets in `NoorWidgets` (lean)
`Q/` = `ThawabForGod/Features/Quran/`; Mushaf = `~/Desktop/Untitled Project/`. Builds on M7.4 (`QuranWidgetSnapshot`, `QuranWidgetKind`, `QuranWidgetFont`, the two links). Nothing here was built or run.
## 1. Goal and scope
- Two new kinds: **Continue Reading** (systemSmall, systemMedium, accessoryRectangular) and **Ayah of the Day** (systemMedium, systemLarge, accessoryRectangular). Timelines run to the next local midnight. Quran text only in the registered Hafs face; if registration fails, the reference only. Taps use `quranPage` / `quranVerse`.
- **Out:** the four prayer/date kinds (untouched, kind strings unchanged), configurable widgets (`StaticConfiguration` only), Live Activities, any app-side publishing (M7.4), the Mac's accessory families (none on macOS).

## 3. Data flow
- **Provider:** `snapshot = QuranWidgetSnapshot.load(from: store)`, `style = .current(from: store)`, `hasHafs = QuranWidgetFontRegistration.register()` (per timeline; cheap after the first). `nextMidnight = DailyAyahRule.calendar.date(byAdding: .day, value: 1, to: startOfDay(now))`.
  - Continue: one entry at `now`, policy `.after(nextMidnight)` (the app reloads by kind on each settled position).
  - Ayah: entries at `now` and `nextMidnight`, policy `.after(nextMidnight)`; the view shows `snapshot.dailyAyah(for: entry.date)`.
  - `placeholder` / `getSnapshot`: the stored snapshot or `nil` (empty state). **No Quran text literal anywhere in code.**
- **Arabic (hard rule, drawing only):** for each `texts[i]`: `QuranAyahText.attributed(texts[i], face: .kfgqpcHafs, scaledSize: size, hafsIsRegistered: true)` + NBSP + `AttributedString(AyahEndMarker.text(verse: first.verse + i))`, pieces joined with a space, in `Font.custom(QuranWidgetFont.postScriptName, size: base, relativeTo: .body)`, `.environment(\.layoutDirection, .rightToLeft)` on that leaf. The stored strings are never edited; the Amiri fallback ranges have no Amiri in the extension, so those few characters draw in the system face (per-character drawing fallback only). `hasHafs == false` → the Arabic slot is replaced by the reference line; the system face never draws Quran text.
- **Reference:** `"\(surahName) \(n(surah)):\(n(first))"`, range `"…–\(n(last))"`, digits via `WidgetLocalization.number`, the numeric part wrapped in FSI…PDI. Surah name: `language == .arabic ? surahNameArabic : surahNameEnglish`.
- **Look:** the `HijriDateWidgetView` treatment: `Theme(accent: style.accent)`, `\.locale = l10n.locale`, layout direction from `style.language`, `.containerBackground(for: .widget) { theme.background }`; text `theme.textPrimary/textSecondary`, label `theme.accent`; `.appFont` for everything but the Arabic.
- **Links:** Continue → `page.map(DeepLink.quranPage) ?? .quranVerse(ayah)`; Ayah → `.quranVerse(first)`; empty → `.quran`. `.widgetURL(...)`.

## 7. Saad's manual checklist
1. **iPhone 17, full:** fresh install, add both widgets before opening the app → the two empty sentences; tap → Quran tab. Open the app once: both fill within a few seconds.
2. Read to page 50 in Mushaf mode, go Home: Continue small/medium show the surah, "Verse N", "Page 50"; tap → page 50 unselected. Switch to separated, scroll to 18:40: the widget says 18:40, no page; tap → 18:40 selected.
3. Ayah medium/large: Arabic in Hafs with ornamented end markers, never the system face; large shows the first enabled translation and its name. Turn all translations off in Settings → large shows Arabic + reference only. Tap → that ayah selected.
4. Lock Screen: both rectangular accessories; Arabic readable in Hafs, Continue text-only.
5. Arabic UI + Arabic-Indic digits: names in Arabic, digits per setting, layout mirrored, the Arabic block always RTL.
6. Next day (or set the device date forward a day): the ayah changes at midnight without opening the app.
7. **Public (`-quranData public`):** Continue never shows a page; Ayah shows Tanzil text, no translation; taps work.
8. **Mac:** add both from the widget gallery on the desktop (medium/large, small); Hafs renders; taps open the reader.
9. The four prayer/date widgets already placed still render (kinds unchanged).
**Reviewer acceptance:** stored `texts` drawn unmodified (only fonts on ranges); no system face on Quran text (`hasHafs == false` → reference only); no corpus / GRDB in the extension; no Quran text literal in code or previews; old kinds untouched; iOS + macOS build clean.
## 8. Risks
- **T5:** no database in the extension; font from the App Group, registered `.process`. **Text:** `QuranAyahText` only sets fonts on ranges; the marker is appended by drawing, not stored.
- **Memory / budget:** 30 days of JSON decoded per timeline; one entry (Continue) or two (Ayah) per day.
- **Accessory rendering:** vibrant mode may not carry the custom face on some Lock Screen styles; then the reference shows (check on device).
- **Font missing on the Mac** (container `nil`): reference only, by design.
